# Changelog

All notable changes to Home Desk. Newest first. Each release lists what changed for people using the panel and for AI agents using the services, and flags anything that needs action (**Action:**) or breaks existing use (**Breaking:**).

Agents: call `home_desk.get_changelog` (optionally with `since` set to the last version you reviewed) instead of reading this file.

## [Unreleased]

### Added
- **Delete a ticket.** A **trash can** icon at the far right of the ticket's button row (on a phone, the end of the icon row) deletes the ticket for good after a confirmation ("Delete Ticket?"). It is not resolved: it leaves the history, with its comments, attachment files and read marks; links to it are removed, and tickets that were merged into it are no longer marked merged. A ticket can't be deleted while the AI Agent is working on it. Deleting a repair's ticket also stops Home Desk opening another for that same repair while it is still there. Administrators only, in the panel only: websocket `home_desk/delete`, and deliberately **no service**, so an AI agent can't delete tickets. The `home_desk_event` bus event fires with `kind: deleted`. **Action:** none

### Removed
- **The `import_file` service and the importer for the author's own `OPERATIONS.md` tracker.** They were only for moving the author's old notes in. **Action:** none unless something calls `home_desk.import_file`.

### Changed
- **The report form is one message box.** The separate title and detail boxes are gone. The first line of the message becomes the ticket's title and the rest its description (a long first line is cut at a word, and the whole message goes in the description). A message, a photo or a voice message is enough on its own; a report with no words is titled "<name> reported a problem" or "... an idea". The upload endpoint `POST /api/home_desk/report` takes a `message` field; the old `title` and `details` fields still work. After sending, the panel closes the keyboard and scrolls back to the top, so the app's back button is no longer left hidden on a phone. **Action:** none
- **The New Ticket dialog uses the panel's own controls.** Kind is a row of pills (Bug, Enhancement, Question, and Task for administrators), priority is the High and Urgent icons beside Create, as in the comment box, and Category is a searchable picker that starts on Home Assistant. **Action:** none
- **A master switch for AI (Settings → AI → Use AI, on by default; turning it off asks first, with a short account of what will happen).** Off hides every AI control and setting in the panel: the AI Action control (Review, Run, Queue), the Queued for AI tab and tile, and the AI cards in Settings. Home Desk enforces it too: Review, Run, Proceed, the test of the AI, assigning a ticket to an AI agent (the panel, `create_ticket` and `update_ticket`), the run services (`claim_run`, `note_run`, `finish_run`), and any service call from the agent's own user or with an `ai:` actor are refused with "AI is switched off in Settings". Turning it off takes every ticket off the AI queue (an `assignee` change by Home Desk on each) and ends any run in progress; turning it on again does not put them back. Websocket `home_desk/settings_save` takes `ai_enabled`. An outside agent using an administrator's token without an `ai:` actor name can't be told apart from a person, so it is not blocked. **Action:** none; the default is on.
- **The AI Agent's own user is read-only until a person presses Proceed, enforced by Home Desk.** It can comment only on a ticket a run is working, and `update_ticket`, `close_ticket`, `link_tickets` and `create_ticket` are refused unless the approved change run is working (on that ticket only; creating needs any change run). Before, nothing but the caller's own tool list stopped a review from changing a ticket. **Action:** none; a service call from that user outside a run is now refused with a clear message.
- **AI comments are easier to read.** The agent guide (`get_guide`) has a new section, "Writing comments people can read": lead with the point in one line, then short bullets with the evidence (entity ids, times, values), a bold label for each group, numbered steps, corrections as "what changed" first, and anything needed from the person last. The default Review With AI prompt and the MCP `add_comment` description say the same, so replies are no longer one long paragraph. **Action:** none. If you edited the Review prompt, Settings shows "The default has changed since you edited this", with Keep Mine and Reset to Default. An agent you run yourself picks up the guide on its next `get_guide`.
- **Choosing Home Desk in Home Assistant's sidebar always opens Home**, even from a ticket, a list or Settings. Home Assistant doesn't tell the panel when the address is unchanged, so the panel watches for the click on the sidebar link. **Action:** none
- **The AI Agent's "nothing to change" findings no longer ask for a go-ahead.** When a Run ends with "What I would change: Nothing", `finish_run` (state `proposed`) records the run as done and adds no Proceed and Dismiss. **Action:** none
- **A dismissed or approved go-ahead card drops its "Waiting for your go-ahead" heading.** It shows only who dismissed or approved it.
- **The Review With AI and Run AI Agent confirmations are shorter and have their own headings** ("Review With AI?", "Run AI Agent?"), and the buttons are Title Case ("Yes, Go Ahead", "Yes, Test It").
- **Settings is never restored when you come back to the panel**, so the sidebar icon opens Home.
- **On a phone, choosing a tab from the drop down shows that list** instead of leaving the open ticket on screen, and a ticket open on a phone has a **search button** next to the three dots (the search bar is hidden while a ticket is open): it goes to the list and puts the cursor in the search box.
- **Start Working is a solid blue button** on an Idea.
- **Resolve and Reopen are outlined buttons that fill solid blue when you point at them.**
- **On a phone** the ticket header puts the title across the full width with one row of buttons under it (back, then previous, next, merge and history); the comment box is tidier when open (AI Action across the width, Start Working on its own line at the top, the priority icons and Resolve on one row, Comment on its own row below), and the comment bar now stays at the bottom of the screen on every phone size (a short ticket used to end mid-screen with the bar floating in the middle, and a long one pushed it off the bottom; the panel is now as tall as the visible screen below where it starts, which in the phone app is under the status bar, and it follows the keyboard: the comment box stays above it). On a phone held on its side the header scrolls instead of taking the screen.

### Fixed
- **"Could not load tickets: [object Object]"** now shows the real message from Home Assistant.
- **A one-line title could be two lines tall** until the font loaded.
- **Entity suggestions failed on newer Home Assistant versions** ("The suggestion lookup failed" in the log, `'ComputedNameType' object has no attribute 'lower'`). An entity's aliases can include Home Assistant's `COMPUTED_NAME` marker, which is not text; it is now left out of the matching. (Found by an AI agent's log check, ticket #260.)
- **Scrolling to the bottom of a ticket could jump back a few lines and hide the end of the last comment.** The title box was re-measured on every redraw, which briefly changed the scrolling area's height and nudged the scroll position; it is now measured only when the title or width changes.

## [1.0.0-beta.1] - 2026-10-21

The first public beta. It covers everything since the internal 0.1.0 below; the panel's look and workflow changed a lot, so read **Breaking** first if you used 0.1.0.

### Breaking
- **Statuses are now `new`, `in_progress`, `resolved` and `closed`: `open` is gone.** Existing `open` tickets become `in_progress` on first start. Setting `status: open` (or `waiting`) still works and means `in_progress`, but responses never contain `open`. **Action:** stop reading or writing `open`.
- **Status now moves by itself.** The first comment or change on a `new` ticket moves it to `in_progress` (changes by Home Assistant, import and Home Desk itself don't count). A `resolved` ticket becomes `closed` automatically after a delay the manager sets in Settings (default 7 days; "straight away" and "never" are options). **Action:** you rarely need to set `status`; use `close_ticket` to resolve.
- **Services (except `get_guide` and `get_changelog`) now need an administrator.** Before, any Home Assistant user could call them and read internal notes or other people's tickets, which the panel never allowed. Calls from automations and scripts (which have no user) still work, and so do calls made with an administrator's token, which is what an AI agent normally uses. **Action:** if an agent or integration calls these services with a non-admin user's token, give it an admin's.
- **The Home Assistant label is gone: it is a category now.** It is removed from tickets and from `list_labels`. Repair tickets get the category Home Assistant, plus the labels Bug and Repair. Tickets that were only labelled Home Assistant are now uncategorised.

### Changed
- **Settings, About: a "Support the Project" link** to the author's Buy Me a Coffee page. Optional, and never expected.
- **List: sorting, a list search, and filters behind an icon.** A sort menu (Default Sort, Last Updated, Date Opened, Priority, Comments, Title, and Date Closed on Completed; picking the chosen one again flips up and down, and the choice is remembered in the browser). The Inbox defaults to newest opened, every other tab to last updated. A search box in each tab (named after it) and the filters open from an icon. An empty list now has the brand logo, a playful message, and Clear Filters when a search or filter is hiding tickets. The Completed tab no longer has a Status filter.
- **Ideas.** The Enhancements tab is now called **Ideas** (the Enhancement label is unchanged).
- **Home page.** Four tiles (Inbox and Working with Urgent and High counts that open the tab on that priority, Queued for AI, and tickets completed in the last 7 days) and a 7-day Ticket Activity graph; "Good Morning" in Title Case.
- **Open ticket chips.** A ticket you only pass through (Previous and Next, a list click, a search) shows as an italic preview chip that the next one replaces, until you act on it or click the chip. Option-click (Alt-click) on a chip's X closes all chips, after a confirmation.
- **AI Action is now staged.** Run and Review are picked, then the main button ("Run AI Agent Now" or "Review With AI Now") starts them and asks about your AI plan; priority can go with them.
- **An AI agent can comment without handing the ticket back.** `add_comment` (and the MCP tool) takes an optional `keep_assigned: true`: the comment, internal or not, is added and the ticket stays assigned to the agent (`ai:AI`) instead of going back to the manager, so tickets the agent is meant to keep watching stay in its queue. The default is unchanged: an agent's comment hands the ticket back. The panel needs no matching option, because a manager's own comments never hand a ticket back. **Action:** none; agents that re-assign after every comment can use the option instead.
- **A notice when your edited Review prompt is older than the default.** Settings shows "The default has changed since you edited this" with **Keep Mine** and **Reset to Default**. The settings now return `agent_prompt_outdated` (true when a saved prompt was written against an older default, or before this was tracked), and `home_desk/settings_save` accepts `agent_prompt_outdated: false` to keep the saved text and hide the notice. Nothing changes in the prompt itself.
- **The MCP bridge can read its token from a file** (`HA_TOKEN_FILE`), so an MCP configuration needs no secret in it. `HA_TOKEN` still works. **Action:** none
- **An About card in Settings**, as in Spatial Context: the version, and links to the release notes (the changelog), the documentation, reporting an issue with Home Desk itself, and the GitHub repository. **Action:** none
- **The three-dot menu is tidy on a phone.** Every item is one line (no more "Report a Problem or Idea" and "Manage Categories" breaking onto two centred lines), with the icons in one aligned column and the words left-aligned; the menu is as wide as its longest item. **Action:** none
- **On a phone the tabs are one drop down and Settings is in the three-dot menu.** The header shows a single button with the list you are on (Inbox, Working, Queued for AI, Enhancements or Completed) and its count, which opens a list of all five with their counts (lit when something changed). The gear moves into the three-dot menu, as **Settings**, so the header has room. Wider screens are unchanged. **Action:** none
- **The description is no longer pinned or squeezed as you scroll.** It is part of the page and scrolls away with it, like the comments below it (a very long one still shows a **Show All** button). The full width view is the way to keep the description in sight while you read a long thread: it has the details and description in a column of their own. **Action:** none
- **Settings: Notifications is one card.** What you are notified about and where it goes were two cards; they are now one, with "Notify me when" and "Send notifications to" as its two parts. **Action:** none
- **A Keyboard Shortcuts card in Settings** lists every key: **R** reply (opens the comment box), **Esc** closes the box or clears the search, **F** full width view, **X** closes the open ticket, the arrow keys and **Enter** in the search drop down, and middle click to close a ticket chip. **Action:** none
- **An Enhancement that has not been started shows a lightbulb status icon** in place of the New circle, green while it has no notes and blue once it has comments (and an ordinary status icon once you Start Working on it): in the list, the open-ticket chips, the search drop down, the Home page and the ticket header. A ticket queued for an AI agent still shows the agent's spark. **Action:** none
- **Enhancements collect notes and start working only when you say so.** A comment or change on an Enhancement (an idea for the future, from you, Home Assistant or an AI agent) no longer moves it from New to In Progress, so it stays in the **Enhancements** tab while you note it. A new **Start Working** button (beside Resolve, on a New Enhancement) moves it to In Progress, and it then shows under **Working** like any other ticket (or **Queued for AI**, if an agent has it). Setting `status: in_progress` through the services does the same. **Action:** agents that comment on an Enhancement should not expect it to start; update its status when work really begins
- **Open tickets are chips in the top bar.** Every ticket you open gets a pill between New Ticket and the search box, with its status icon, number, title and a close button, and keeps it until you close it; the one you are on is tinted. Up to eight are kept (opening a ninth drops the oldest you are not on), and they shrink to share the room, then scroll. Middle-click or the ✕ closes one (closing the one you are on opens its neighbour, or shows the list). Chips are remembered in the browser, drop off when a ticket is merged away, show a dot when the ticket changed and a spark while an AI agent is working on it, and are hidden on a phone. The ticket header's meta line sits a little closer to the title, with the number, category and labels row a little lower and a little more room above the line under it. **Action:** none
- **An updated logo.** The integration's logo and icon (light and dark), the mark in the panel's header and the favicon, avatars and social images use the new brand pack (a slimmer tick tip on the house). **Action:** none
- **A full width ticket view.** A new icon to the right of the history icon (or the **F** key, when you are not typing somewhere) gives the ticket the whole page: the header (title, previous and next, merge, and the icon again to leave) runs across the top, the details, description, attachments and related items are in a panel on the left, and the right is only the comments, with the comment box under them. The left panel is the same width as the list, scrolls as one, and lists the ticket's history (changes, not comments) under the description, always, so the header has no history icon there. Previous and next keep stepping through the list you came from. It is not offered on a phone, where the ticket already fills the screen. **Action:** none
- **The comment box is a slim strip until you want it, and the R key opens it.** Pointing at it or clicking into it opens it (upward, over the thread, so nothing jumps), and it stays open while it holds a draft, a picked priority or a picked Queue. **R** (for reply; when you are not typing somewhere) opens it and puts the cursor in it. **Escape** closes it, keeping any draft, and so does **R** when the cursor is not in the box (inside it, R is just a letter). Home Assistant's own shortcuts (C, E, D, M, A) are left alone. On a touch screen it opens when tapped. **Action:** none
- **A bar across the top of the page, and searching for a ticket's number finds exactly that ticket.** **New Ticket** (always with its words) is at the left and the search box, a quarter of the width, at the right, over both the list and the open ticket. **Select Tickets** and the filters (Category, Priority, Label, and Show on the Completed tab) have their own bar at the top of the list, always showing: there is no Filters button to open any more. Typing just a number, `244` or `#244`, shows ticket #244 whichever tab or filter it is under; the same search through the services (`list_tickets` with `query`) now returns exactly that ticket instead of every ticket with those digits in its text, and falls back to a text search if there is no such ticket. **Action:** none
- **The tabs no longer overlap, and "All" became "Completed".** Every open ticket is in exactly one tab, the first that fits: **Queued for AI**, then **Enhancements**, then **Inbox** (New: not looked at yet, or reopened by Home Assistant or an AI agent), then **Working** (renamed from In Progress: what you and the other admins are working on, including tickets an AI agent has answered). **Completed** shows resolved and closed tickets; its Show filter reaches Open, History and Everything. The Home tiles follow. A tab you had open is kept under its new name.
- **A ticket reopened by Home Assistant or an AI agent goes back to New** (it used to go to In Progress), so it shows in the Inbox. This covers a repair that returns or stops being ignored, and an agent setting a resolved or closed ticket to `in_progress`. A person's reopen is unchanged. **Action:** agents reopening a ticket should expect `new`, not `in_progress`
- **"Assign to AI Agent" is now "Queue for AI Agent", and the AI buttons are tidier.** **Queue for AI Agent** sits beside the priority icons: you pick it, and it is applied with the main button (which reads "Comment and Queue for AI Agent"), as before. It is no longer pre-selected after an agent replies. A queued ticket shows **Queued for AI Agent** (it was "With AI Agent"; the list tab is **Queued for AI**). A separate **AI Action** control is for things that happen at once, one click each, with your typed comment posted first: **Review** (with the same confirmation) and, later, **Run**. Both are hidden or reduced on resolved and closed tickets, and the priority icons are hidden there too. Stored data is unchanged: a queued ticket is still `assignee: ai:AI`. **Action:** none for agents; the default Review prompt now says "Queue for AI Agent". A prompt you have edited is not changed
- **A repair you ignore in Home Assistant now resolves its ticket, instead of adding Blocked.** The ticket is resolved with "Ignored in Home Assistant", no ticket is opened for a repair that is already ignored, and it reopens if the repair stops being ignored. If you reopen it yourself while the repair is still ignored it is left open. This stops dismissed repairs that Home Assistant restores at every start (such as the persistent Proxmox ones) from reopening their ticket. Blocked labels Home Desk added for ignored repairs are removed. **Action:** agents should not expect Blocked on a repair ticket
- **"Restart required" repairs (HACS and others) are skipped.** They say an update is waiting for a restart, not that anything is wrong, and they made tickets for nothing.
- **The agent guide now lists every service's parameters** (`link_tickets` takes `ticket_id` and `other_id`; `update_label`, `delete_label`, `update_category`, `delete_category`, `merge_tickets`, `import_file`, `get_guide` and `get_changelog` were thin or missing).
- **The agent guide and the MCP bridge now say plainly how to find the tickets handed to you.** They are assigned to `ai:AI` (shown as "With AI Agent") whatever AI you are, not to your own name; older tickets may carry `ai:Claude`, which means the same. Look for both with `list_tickets`. Nothing changes in the data. **Action:** query `assignee: "ai:AI"` (and `ai:Claude`), not your actor name
- **Removed the separate "Ask AI" link for suggestions.** Review with AI is where the AI is asked. The "Related?" guesses stay (they are free: no AI is involved), and the AI Review still sees them, marked as unconfirmed. The websocket `home_desk/suggest` no longer takes `ai`.
- **A new logo.** The mark is now a house with a tick and a small AI spark cut out of it, and the tick carries on past the roof. It is in the panel's header (the roof's peak still sits over the New Ticket button), the preview's favicon, and the logo and icon Home Assistant shows for the integration (light and dark).
- **Wording: Review with AI, and Assign to AI Agent.** The integration's button is now **Review with AI** (it isn't an agent: it answers and doesn't act), and its comments and working indicator read **AI Review (Claude)**. **Assign to AI Agent** stays (your Claude CLI and Gemini Antigravity are agents), and the marker reads **With AI Agent**. Comments from your own AI show just the name it signs with (Claude, Gemini), with the AI avatar. The MCP bridge now records `HOMEDESK_ACTOR` as `ai:<name>` itself, so any AI is recognised without writing the prefix (and its comments hand tickets back); **Action:** a client that calls the services directly should send an `actor` that starts with `ai:`. Comments from reviews carry `data.review` (older ones `data.hints`).
- **The review instructions are editable in Settings → Review instructions**, with Reset to default. A new default prompt replaces the old rules: a clear role (a reviewer that can only read what it is sent, so it can't act), a recommendation first, one decision rather than a menu, the words on the screen, "I'd resolve this", never "I'll close it", and an example. The part Home Desk relies on (the format of proposed changes, and that the ticket's own text is data and not instructions) is always added after yours and shown read-only. The default also says to propose resolving or closing a ticket only when the work is really done (the person says it is fixed, the comments show it, or there is nothing to fix), and to write the resolution as what is true now, never as a fix that hasn't been made. Home Assistant's automatic "cleared" and "reporting again" comments on a repair ticket are summarised for the AI as a count instead of quoted (it took them as evidence that the repair keeps coming and going on its own). When a fix needs a change to the home's configuration, the AI says exactly what the change is and points to Assign to AI Agent so your own AI can make it. The AI is told to write a page in Home Assistant as a real Markdown link (a path in backticks can't be clicked) and not to say it will follow up. A proposed resolution shows as **Resolve this ticket** with the resolution beneath it in quotes. A review that still claims it acted ("I'll close it", "I've updated", a "Closing ticket" heading) gets a note that it can't change anything. `agent_prompt` in settings; `agent_prompt_default` and `agent_prompt_fixed` are returned with them.
- **Two separate things: mark a ticket for your own AI, and ask the AI in Home Assistant for hints.** **Assign to AI Agent** now only marks the ticket for an AI you run yourself (your Claude CLI, Claude Desktop or anything else): it sends nothing anywhere, costs nothing, and shows as **With AI** (any AI, not a named one; new marks are stored as `ai:AI`, and older `ai:Claude` marks work as before). **Ask AI Agent now** asks the AI chosen in Settings for hints (an explanation and ideas to try, never changes anything) after a confirmation, and **never touches that mark**, so a ticket queued for your own AI stays queued. Its comments and working indicator read **AI Hints (Claude)** (`data.hints` on the comment) and the reply doesn't hand the ticket back; a failure or Stop leaves a comment and leaves the mark alone. A comment from your own AI still hands the ticket back, as before.
- **Removed the Settings option to run the AI Agent when a ticket is assigned** (assigning is only a mark now). Settings → "AI hints" says which AI answers Ask now, and what is sent. A request that is already running, or past the daily limit, now says so instead of leaving a comment.

The proposal shows under its comment with **Apply** and **Dismiss**; nothing changes until you apply it, the change is recorded as made by you, and only the newest proposal can be applied. The agent is also told to make a decision and propose it, not to ask "which would you prefer?", and never to say it has changed something or that it can close, label or edit a ticket (it can only propose), and to use the words on the screen: "press Resolve", not "update the status to closed". On a ticket, **Ask Claude now** has the built-in AI agent read it and reply straight away, after a confirmation that says it uses your AI plan. **Assign to AI Agent** now only hands the ticket over, for an agent outside Home Assistant (such as your Claude CLI) to pick up later, unless Settings is set to run the AI Agent on assignment (now off by default; it asks first when on). ### Changed
- Settings, Home, and the household report form now follow Home Assistant's card style: a lighter box with its title inside, filled fields, HA-style switches and select fields. Text fields in dialogs are filled fields too.
### Fixed
- **A Home Assistant deprecation warning from the suggestions** ("device_registry.devices is being used as a mapping", logged once per start, from `suggest.py`): the device registry is now read by iterating it, as Home Assistant asks. It would have stopped working in Home Assistant 2027.9.
- **Repairs tickets no longer flip between Resolved and In Progress on every restart, and a repair that really clears now resolves its ticket.** Two causes. (1) Right after Home Assistant starts, many integrations (Spook, for one) have not raised their repairs again yet, and Home Desk took "not there yet" for "cleared": it resolved the ticket, then reopened it when the repair came back. Now a repair that is missing at start (or that Home Assistant lists only as an inactive record, as it does for Spook's repairs after a restart) is only counted as cleared if it is still not reported 15 minutes later, and one that disappears while Home Assistant runs waits 2 minutes (an integration reload removes and re-raises its repairs), or the rest of those 15 minutes if it disappears soon after a start (Spook removes its old repairs as it starts and raises them again minutes later); if it is reported again in that time, nothing happens to the ticket. (2) Since repairs of one kind began sharing a ticket, a repair that cleared could not find its ticket (the registry no longer knew which group it belonged to), so grouped tickets such as #230 to #232 never resolved at all; they are now found through the repairs they list. A ticket resolved after a start says so in its resolution.
- **Reopening a ticket drops its old resolution.** A ticket moved from Resolved or Closed back to an active status no longer keeps the resolution text from when it was closed (it stays on the timeline).
- Scrolling to the bottom of a ticket with a short thread kept flicking back up: the long description folded away, which shortened the page so much that it jumped to the top and unfolded again, over and over. It now leaves a short thread alone.
- Drop-down menus (such as the AI Agent choice in Settings) were cut off inside a Settings card; they now open over everything and are as wide as their choices.
- Saving the speech-to-text engine and "Write out voice messages" in Settings was refused by the websocket schema.
- **"Updated … by …" on every ticket.** The list rows and the ticket's header now say when it last changed and who changed it (a person, an AI agent, or Home Assistant). Tickets and the websocket `home_desk/list` and `home_desk/get` carry `updated_by`.
- **Unread marks.** A ticket someone else changed since you last looked (a new request, a comment, a status change, an AI agent's update) shows a dot and a bold title, says what changed ("Claude commented 25 minutes ago"), and lights up its tab's count. Opening a ticket marks it read, the open ticket marks what is new on its timeline, and "Mark All as Read" (More options) and "Mark as read" (on a selection) clear it. It is remembered per person on the server, and everything starts as read.
- Websocket command `home_desk/mark_read` (admin) and, on `home_desk/list`, `unread` and `activity` for the signed-in person. Services and the MCP tools are unchanged.
- **Select several tickets and merge them.** Administrators tick tickets in the list (the state icon turns into a checkbox on hover, shift-click selects a range, a long press or the Select button works on touch), then choose Merge, pick the one to keep (the oldest is suggested) and confirm.
- **Categories: what part of the smart home a ticket is about.** One optional category per ticket (Home Assistant, Network, Lighting...). Home Assistant is built in and locked; the rest are made by the manager (Manage Categories in the panel) and by agents. New services `list_categories`, `create_category`, `update_category` and `delete_category` (agents may delete only a category nothing uses), and a `category` field on `create_ticket`, `update_ticket` and `list_tickets` (`none` finds uncategorised tickets). A ticket's category must already exist: create it first. `get_stats` adds `no_category` and `categories`. MCP: `list_categories`, `create_category`, `update_category`, `delete_category`, and `category` on create, update and list. **Action:** agents, see "Categorise what you touch" in `get_guide`.
- **Assign a ticket to an AI agent.** In the panel the only assignee is the AI agent (named `ai:<name>`). Assigning fires a `home_desk_event` of kind `assigned` so an automation can start the agent, and when the agent comments on a ticket assigned to it, the ticket is handed back (the assignee is cleared). Events carry `with_agent` and `category`. `get_stats` adds `with_agent`.
- **Settings page** (the cog in the panel, admins only): the close-resolved-tickets delay, which AI agent to use, a switch for tickets from Repairs, and each manager's own notification options (stored now; sending notifications comes later).
- **Panel redesign:** a flat full-width ticket with the title, status, priority, category and labels pinned at the top; a long description collapses to one line as you scroll; comments with avatars and your Home Assistant profile picture; the comment box docked at the bottom with a priority control and "Assign to AI Agent" (switched on by default after the agent has replied); a history view with each change as a line; a new-ticket button at the left of the toolbar; priority as a warning icon in the list; HA-style Manage Categories page.

- **Household report form with photos and a voice message.** A household member picks Problem or Suggestion, types a line and optional detail, adds up to six photos (shrunk in the browser) and records or attaches a voice message of up to three minutes. Home Assistant's speech-to-text writes the message out as a quoted block in the ticket's description, and the recording is kept (Settings: switch it off or choose the speech-to-text engine; the default is the one Assist uses). The form uploads to `POST /api/home_desk/report`; files are stored in `home_desk_attachments/` in your config folder, checked by their contents (JPEG, PNG, WebP or a sound; nothing that can carry script), served only to administrators and the person who sent them, and a person can send ten reports an hour. Tickets gain an `attachments` list (id, kind, mime, name, size, by, seconds, transcript), `attachment_count` in lists and an `attachment` kind of timeline entry. Photos and voice messages show on the ticket; the list shows a paperclip with the count. A microphone needs https (or localhost); without it the form offers a file picker for a recording instead. **Action:** agents, `get_ticket` shows `attachments`; the words of a voice message are already in `description` (and in `transcript`).

- **Agents can manage labels.** New services `create_label`, `update_label` and `delete_label` (and MCP tools of the same names), matching the category ones: create with a name, colour, description and icon, rename or recolour (tickets keep the label), and delete only a label no ticket uses. The built-in labels can't be changed or deleted.

- **Repairs of the same kind share one ticket, and tickets can be merged.** Repairs from one integration with the same issue type (for example every "resource exception" from Proxmox) now raise a single ticket that lists what is affected (`Affected (2): pve, pve2`). It resolves when all of them clear, reopens when one returns, and comments when one joins or clears. A repair with no issue type keeps its own ticket. Existing per-repair tickets are folded together the first time Home Assistant reports them again. **Merge tickets** (the merge button beside History in the panel, the `merge_tickets` service and MCP tool, `home_desk/merge`) folds duplicates into one: the others' comments (marked "from #N"), description, labels, entities, files and linked repairs move over, anything that linked to them links to the kept ticket, and they are closed as "Merged into #N" (a `merged_into` field). A merged repair doesn't open a new ticket when it changes again. Admin only; it can't be undone. **Action:** repair tickets now have the source key `repair:<integration>:<issue type>`; an agent that looked tickets up by `repair:<integration>:<issue id>` should list by title or label instead.
- **An "Assigned to AI" tab** in the panel (replacing the AI Agent filter), and the Raised By filter now appears only while you are filtering by a person (click a name in the list). The priority filter no longer offers Low.

### Changed
- Titles are limited to 300 characters, comments, descriptions and resolutions to 100,000, and label and category names to 80 (the longest imported ticket is about 21,000). Pictures in ticket text are shown as links, not loaded, and forms, styles and SVG are removed.
- Panel: an amber **Blocked** item in the list and on the ticket; a "With AI Agent" filter; the brand mark in the header; screen-reader and keyboard improvements and reduced-motion support.

### Breaking (labels and views)
- **Tags are now labels, and `type` is gone.** Like GitHub, a ticket is categorised by labels. Renames: services `list_tags` → `list_labels`; `tags`/`add_tags`/`remove_tags` → `labels`/`add_labels`/`remove_labels`; the `tag` filter in `list_tickets` → `label`; the `tags` field on tickets and in `get_stats` → `labels`; websocket `tags`/`tag_*` → `labels`/`label_*`; MCP tool `list_tags` → `list_labels`. The old names are still accepted by the services (and by import files) and translated, but responses use the new names, so **Action:** read `labels` where you read `tags`, and stop reading `type`.
- **The `waiting` status is gone.** Use the **Blocked** label. Setting `status: waiting` still works and becomes `open` plus the Blocked label.
- **Statuses are now `new`, `open`, `in_progress`, `resolved`, `closed`.**
- `list_tickets` no longer has a `type` filter; filter by `label` (Bug, Enhancement, ...). Tickets labelled **History** are left out unless `include_history` is true (this replaces the old `log` type).

### Added (repairs, labels)

The ticket resolves itself when HA clears the repair, reopens if it comes back, and gets the Blocked label while the repair is ignored in HA.
